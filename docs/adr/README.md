# Architecture Decision Records

Decisions that are **settled**, with the alternative that was rejected and the evidence that settled it.
Not proposals — GitHub issues hold open work, and these are the record of what was already resolved.

Written because five review rounds kept re-deriving the same context, and one decision (0002) was nearly
re-proposed by the same agent that had rejected it a batch earlier. `docs/agents/domain.md` says to create
these lazily, when decisions actually get resolved; that point arrived.

| [0035](0035-a-monitor-duration-is-the-debuggers-measurement-and-says-so.md) | Lock contention is reported as events with no suspend, and the duration is **the debugger's own measurement** — no monitor event carries one — so every reply that prints one says whose it is. `min_duration_ms` filters what you READ, not what crosses the wire. `ClassOnly` means the lock's type on the wait pair and the blocking CODE's class on the contended pair, measured, so `monitor_class` is refused where it would mislead. Amends ADR-0027 |
| [0036](0036-an-invoking-trace-expr-is-refused-where-the-thread-does-not-own-the-lock.md) | A `trace_expr` that CALLS A METHOD is refused on **`blocked`** — the one monitor kind of four where the hit thread does not own the monitor in its own snapshot. Accepted on `acquired`, `wait` and `waited`, measured: an invocation returns promptly on all three, which also closes the glossary's open question about `waited`. Measured: the invocation outruns its budget, JDWP cannot cancel it, and the JVM **re-suspends the thread when the call finally returns** — 1.2 s after the capture path resumed it — leaving it suspended for ever with no watchdog cover. Verifying the resume was implemented first and does nothing, because the suspend arrives after there is anything left to verify. Extends ADR-0035 |
| [0037](0037-a-named-query-suppresses-its-own-flush-and-is-found-in-the-frame-or-not-at-all.md) | `debug.run_named_query` runs a `@NamedQuery` through the application's own `EntityManager`. Its read-only promise is **not achievable by restraint**: JPA's default `FlushModeType.AUTO` makes `getResultList()` write, so the tool sets `COMMIT` on the query it created, states the accuracy cost in every reply, and **refuses to run** when it cannot. Discovery is the **frame only** — measured: `Instances` on the `EntityManager` interface answers 0 while the concrete class answers 1, and JDWP has no find-implementors command — so with no bean in the frame it refuses and names the `debug.list_instances` two-step rather than guessing provider class names. Rows are a **row projection**: fields read, nothing invoked, so no lazy association is initialised. Extends ADR-0032, amends the **Read-only** glossary entry |
| [0038](0038-independent-reads-share-one-round-trip-and-independence-is-a-licence.md) | **Independent reads** may be in flight together, correlated by packet id, and the transport already allowed it: `send_command` was `&self`, replies were already routed by id, and the serialisation was one `&mut self` wrapper above it. So the primitive is a **split** — `issue` + `InFlight::reply` — not a mechanism, and the framing risk #100 names is untouched because framing lives in the reader task (ADR-0018). Every reply is awaited even after one fails, since JDWP cannot recall a command: abandoning the wait abandons only the answer. The 16-command window is a **deadlock bound** before it is a knob, and the arithmetic is written out. It buys **round trips, not packets**, so every packet-bound test holds — asserted, not assumed. Independence is per sequence, so exactly **one** call site is licensed — `debug.run_named_query`'s row projection, as **two** waves, because a row's field ids come from its own type and that dependency is asserted against a mixed-type result whose merged-wave form was built and found to **mislabel** rows, not merely fail them. Measured through the relay: **17.67 → 1.78 ms/row** of wire time on a row of primitives (9.9x), and **79.19 → 63.18** on the realistic entity, where six of eight round trips per row are still-serialised `render_value` string and association reads — both numbers quoted, because either alone misleads. A **second** call site follows — `debug.get_stack --include_variables`, as three waves — where the larger finding was not the waving: its per-method line and variable tables were being read **per frame**, so a warm 66-frame walk went **209 -> 90 commands and 227.1 -> 28.1 round trips**, asserted by a cassette census (deterministic) as well as by the wire. It is refused on the deep path, because invoking `toString()` invalidates every frame id and because that walk stops on a budget, making a prefetch speculative — and **speculation is the only thing that could raise the packet count**, which is the invariant every conversion protects. A **third** call site is a dump's triage — two reads per thread, under the suspension — chunked by the window so the freeze budget is still handed back, taking a 20-thread dump's **held time 3731ms -> 1175ms (-68%)** at the same 763 packets. That broke ADR-0011's `held ≈ packets × (our processing + RTT)`, which is a **caller-facing** model: it is now `held ≈ round_trips × RTT + packets × our processing`, TEST-13's test divides by round trips instead, and a cost line reports **both** figures (`763 JDWP packet(s) in ~180 round trip(s)`) because they answer different questions. The correlation test's first version passed with a window of one and proved nothing; the negative control is what found that |

The property defended is **provenance, not length**: an entry earns its lines by recording a distinction that was got wrong at least once, so `Copy` carries why one classloader bug failed loudly and its twin failed silently, `Invoke-free` unifies three separately-discovered hazards, and `Filter pin` exists to stop ADR-0022 and ADR-0027 reading as a contradiction. | [0040](0040-a-session-default-not-a-second-tool-family-and-never-a-merge.md) | `debug.attach` and `debug.launch` take a `trace_expr` that every stop point naming none records — a **session default**, not the `add_watch`/`evaluate_watches` family the issue found upstream. | [0041](0041-the-server-returns-the-set-and-the-client-stores-it.md) | A **stop-point set** is content the server returns and the **client** stores: `debug.list_stop_points {export:true}` emits it, the new `debug.arm_stop_points` takes it back, and nothing here touches the filesystem. | [0042](0042-an-investigation-report-is-unredacted-and-says-so-first.md) | `debug.export_investigation` emits the session as one **Markdown** report — attach target, VM version, every stop point with its measured cost, the snapshots still held, the drift verdicts — because the findings are the deliverable and an investigation was otherwise readable once, by one reader, in a context window that gets summarised. **Unredacted, opening with a paragraph that says so before any content**, since a reader who scrolled past the warning has already read the payloads. The stop-point section is `list_stop_points`' own renderer, so it cannot drift, and it brings the staleness verdict for free. **It never clears** — the test calls it twice, because one call cannot tell reading from draining — and it **cannot** preserve a trace beyond the ring, which would need the write path ADR-0041 declined, so it states the loss (`trace_seq` against `traces.len()`) instead |

| [0049](0049-a-render-reads-through-a-closed-pair-and-the-stated-debuggee-is-written-not-recorded.md) | **A render reads through a closed pair of adapters, and the stated debuggee is written rather than recorded.** CLEAN-7 (#190): `JdwpConnection`'s one constructor opens a `TcpStream`, so 34 of the 118 reply renderers could only ever be exercised against a live JVM — and **30 `#[ignore]`d tests launch a probe, attach, ask a question and assert on a string without ever making the debuggee do anything**. The cost is not only seconds: `generics.rs` is 318 lines of recursive descent whose *rendered listing* had no test at all, because reaching a listing meant launching a JVM. `Reads` is the narrowest fix — **invoke-free** class and member metadata, satisfied by exactly two adapters, the live connection and a **stated debuggee** written as data. **A closed enum, not a trait**, and the deciding reason is not that `async fn` in traits is dyn-incompatible: a closed type keeps the set of adapters a question *this crate* answers, so a third is an edit in front of a reviewer rather than an `impl` anybody can write — which is what keeps **ADR-0001** intact as the seam grows.
