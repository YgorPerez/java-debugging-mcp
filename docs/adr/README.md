# Architecture Decision Records

Decisions that are **settled**, with the alternative that was rejected and the evidence that settled it.
Not proposals — `TODO.md` holds open work, and these are the record of what was already resolved.

Written because five review rounds kept re-deriving the same context, and one decision (0002) was nearly
re-proposed by the same agent that had rejected it a batch earlier. `docs/agents/domain.md` says to create
these lazily, when decisions actually get resolved; that point arrived.

| [0012](0012-one-task-owns-stdout.md) | One task owns stdout |

| [0016](0016-a-class-root-is-not-a-source-root-and-a-pop-is-not-a-flag.md) | Compiled output gets its own `class_roots`, and `pop_frame` is its own tool rather than a flag on a reload |
| [0017](0017-an-exception-message-is-read-as-a-field-except-the-one-the-jvm-never-stores.md) | An exception's message is read as a field, with one narrowly-gated invocation for the helpful NPE the JVM never stores |

| [0019](0019-arming-covers-every-classloader-reading-picks-one-and-says-so.md) | Arming covers every classloader's copy of a class; a read picks one, says so, and can be pinned |
| [0020](0020-a-conditional-stop-point-decides-on-one-thread-and-escalates.md) | A conditional stop point decides on one thread, and escalates to a VM-wide suspend only when the condition holds |
| [0021](0021-one-thread-is-suspended-by-its-own-tool-and-invocation-is-not-what-it-unlocks.md) | A per-thread suspend is its own pair of tools, and what it unlocks is every read of a frame — but not method invocation, which JDWP reserves for an event-suspended thread |
| [0022](0022-an-object-handle-is-printed-weak-and-never-pinned.md) | An object handle is the `@0x…` every reply prints, and it stays a weak reference — nothing is pinned |
| [0023](0023-a-heap-query-ships-and-reports-the-pause-it-imposed.md) | The heap query ships and reports the pause it imposed, rather than refusing or asking permission |
| [0024](0024-per-test-timings-come-from-libtest.md) | Per-test timings come from libtest's `--report-time` — so the runner builds and runs in two steps — and not from cargo-nextest, whose process-per-test scheduling is the one variable that must not move while the flakes are open |
| [0025](0025-the-suite-is-sharded-two-ways-by-measured-duration.md) | The suite is sharded two ways per JDK, split by *measured* duration rather than by name — and stops at two. Amended twice: the 70 s floor died with TEST-30 and the 35 s one with TEST-35, and with no floor left a third shard is measured at **0.1 s** for +50 % runners |
| [0026](0026-a-spent-stop-point-is-reported-spent-and-clearing-it-sends-nothing.md) | A stop point whose `hit_count` has fired is reported **SPENT** — a third state, because the *debuggee* removed it — and clearing it sends no packet, since JDWP request ids recur and a `Clear` for a deleted id can land on somebody else's |
| [0027](0027-an-instance-filter-is-offered-only-where-it-was-measured-to-apply.md) | `instance_id` is offered only on the stop-point kinds where `InstanceOnly` was **measured** to apply — HotSpot accepts it on three more and silently ignores it — and the arm reply says that an armed filter *pins* its object |
| [0028](0028-an-armed-exact-name-stop-point-keeps-its-class-load-watch.md) | An armed **exact-name** stop point keeps its `CLASS_PREPARE` watch for life, so a copy loaded by a redeploy's new classloader is armed into the same `bp_` id — rejecting the alternative of merely *reporting* staleness, which is false exactly when the bug bites |
| [0029](0029-a-source-window-is-checked-on-two-axes-and-mtime-is-a-hint.md) | A `debug.source` window is checked on **two independent axes** — JVM against build, build against the `.java` shown — because they have different remedies, and the issue's own prescribed mechanism was silent on the five files it was filed about. The timestamp half is labelled a hint, not a verdict |
| [0030](0030-a-redefine-forecast-states-a-refusal-confidently-and-a-pass-weakly.md) | `check_stale` forecasts which of `HotSpot`'s refusals a redefinition would hit. A **refusal is stated confidently, a pass weakly** — six of the twelve codes are derivable from a structural diff and six are not — and every prediction is checked against a real `RedefineClasses` on three JDKs |
| [0031](0031-an-escalated-trace-is-reported-not-refused.md) | A `trace:true` stop point whose suspend policy has been taken over by a suspending one at the same location is **reported, not refused** — on both arm replies and in the listing, which stops calling it a bare `(trace)`. Rejecting the refusal precedent (ADR-0027) because the casualty is an *older* stop point's promise, not a lie about the new one |
| [0032](0032-an-unfetched-lazy-association-is-a-third-answer.md) | An UNFETCHED Hibernate association is a **third answer** alongside a value and `null`, so a chain walk stops and says which of the three it is. The marker **interface** decides; the class **name** is only a cost gate, because asking unconditionally cost a 5-link non-Hibernate chain +44% in packets |
| [0033](0033-generic-types-replace-erased-ones-and-the-fallback-is-the-design.md) | The four generic JDWP commands **replace** their plain twins, so every type string carries its type arguments — with a full JVMS 4.7.9.1 parser rather than a verbatim signature, and a three-layer fallback because the attribute is optional and the wire answers with an EMPTY STRING when it is absent |
| [0034](0034-a-condition-may-name-what-the-hit-carries-not-only-what-the-frame-holds.md) | All four stop-point kinds take a `condition`, and a condition may name what the **hit** carries as well as what the frame holds — `exception` on a throw, `newValue` on a write, bound through the existing `@0x…` handle head. `!` joins the grammar, binding tighter than `&&`. Amends ADR-0020 |
| [0035](0035-a-monitor-duration-is-the-debuggers-measurement-and-says-so.md) | Lock contention is reported as events with no suspend, and the duration is **the debugger's own measurement** — no monitor event carries one — so every reply that prints one says whose it is. `min_duration_ms` filters what you READ, not what crosses the wire. `ClassOnly` means the lock's type on the wait pair and the blocking CODE's class on the contended pair, measured, so `monitor_class` is refused where it would mislead. Amends ADR-0027 |
| [0036](0036-an-invoking-trace-expr-is-refused-where-the-thread-does-not-own-the-lock.md) | A `trace_expr` that CALLS A METHOD is refused on **`blocked`** — the one monitor kind of four where the hit thread does not own the monitor in its own snapshot. Accepted on `acquired`, `wait` and `waited`, measured: an invocation returns promptly on all three, which also closes the glossary's open question about `waited`. Measured: the invocation outruns its budget, JDWP cannot cancel it, and the JVM **re-suspends the thread when the call finally returns** — 1.2 s after the capture path resumed it — leaving it suspended for ever with no watchdog cover. Verifying the resume was implemented first and does nothing, because the suspend arrives after there is anything left to verify. Extends ADR-0035 |
| [0037](0037-a-named-query-suppresses-its-own-flush-and-is-found-in-the-frame-or-not-at-all.md) | `debug.run_named_query` runs a `@NamedQuery` through the application's own `EntityManager`. Its read-only promise is **not achievable by restraint**: JPA's default `FlushModeType.AUTO` makes `getResultList()` write, so the tool sets `COMMIT` on the query it created, states the accuracy cost in every reply, and **refuses to run** when it cannot. Discovery is the **frame only** — measured: `Instances` on the `EntityManager` interface answers 0 while the concrete class answers 1, and JDWP has no find-implementors command — so with no bean in the frame it refuses and names the `debug.list_instances` two-step rather than guessing provider class names. Rows are a **row projection**: fields read, nothing invoked, so no lazy association is initialised. Extends ADR-0032, amends the **Read-only** glossary entry |
| [0038](0038-independent-reads-share-one-round-trip-and-independence-is-a-licence.md) | **Independent reads** may be in flight together, correlated by packet id, and the transport already allowed it: `send_command` was `&self`, replies were already routed by id, and the serialisation was one `&mut self` wrapper above it. So the primitive is a **split** — `issue` + `InFlight::reply` — not a mechanism, and the framing risk #100 names is untouched because framing lives in the reader task (ADR-0018). Every reply is awaited even after one fails, since JDWP cannot recall a command: abandoning the wait abandons only the answer. The 16-command window is a **deadlock bound** before it is a knob, and the arithmetic is written out. It buys **round trips, not packets**, so every packet-bound test holds — asserted, not assumed. Independence is per sequence, so exactly **one** call site is licensed — `debug.run_named_query`'s row projection, as **two** waves, because a row's field ids come from its own type and that dependency is asserted against a mixed-type result whose merged-wave form was built and found to **mislabel** rows, not merely fail them. Measured through the relay: **17.67 → 1.78 ms/row** of wire time on a row of primitives (9.9x), and **79.19 → 63.18** on the realistic entity, where six of eight round trips per row are still-serialised `render_value` string and association reads — both numbers quoted, because either alone misleads. A **second** call site follows — `debug.get_stack --include_variables`, as three waves — where the larger finding was not the waving: its per-method line and variable tables were being read **per frame**, so a warm 66-frame walk went **209 -> 90 commands and 227.1 -> 28.1 round trips**, asserted by a cassette census (deterministic) as well as by the wire. It is refused on the deep path, because invoking `toString()` invalidates every frame id and because that walk stops on a budget, making a prefetch speculative — and **speculation is the only thing that could raise the packet count**, which is the invariant every conversion protects. A **third** call site is a dump's triage — two reads per thread, under the suspension — chunked by the window so the freeze budget is still handed back, taking a 20-thread dump's **held time 3731ms -> 1175ms (-68%)** at the same 763 packets. That broke ADR-0011's `held ≈ packets × (our processing + RTT)`, which is a **caller-facing** model: it is now `held ≈ round_trips × RTT + packets × our processing`, TEST-13's test divides by round trips instead, and a cost line reports **both** figures (`763 JDWP packet(s) in ~180 round trip(s)`) because they answer different questions. The correlation test's first version passed with a window of one and proved nothing; the negative control is what found that |

| [0039](0039-the-glossary-is-long-form-on-purpose-and-the-length-is-the-evidence.md) | `CONTEXT.md` is **long-form on purpose** — ~1,190 lines for 151 terms, against the `/domain-modeling` skill's "one or two sentences max". The property defended is **provenance, not length**: an entry earns its lines by recording a distinction that was got wrong at least once, so `Copy` carries why one classloader bug failed loudly and its twin failed silently, `Invoke-free` unifies three separately-discovered hazards, and `Filter pin` exists to stop ADR-0022 and ADR-0027 reading as a contradiction. Compression is lossy in a way nothing else recovers — `TODO.md` and these ADRs are not indexed *by word*, which is the index a reader has when they are about to use the wrong one. Implementation detail stays out, unrelaxed. New entries still start tight |
| [0040](0040-a-session-default-not-a-second-tool-family-and-never-a-merge.md) | `debug.attach` and `debug.launch` take a `trace_expr` that every stop point naming none records — a **session default**, not the `add_watch`/`evaluate_watches` family the issue found upstream. Exists mostly to be read next to **ADR-0015**, which decided the opposite-looking thing and whose rule (*a flag may not change what the question was*) points **here**: 0015 rejected one name for two questions, this rejects two names for one — "record these expressions at hits" is already named `trace_expr` on all five stop-point tools. 0015's discovery argument does not transfer (nobody reaches for `add_watch` without having met `trace_expr`), and its two-independent-budgets argument inverts: there is **one** cost, paid inside the window a hit holds the thread, so it must stay one number. **Never a merge** — a caller naming four expressions is already at the cap, so appending any session list would push past it and drop the tail silently, making the cap the cause of the loss it exists to reveal. Evaluated only at a stop the caller already caused, never at every event, which is the safety half a tool family would have named wrongly. `inherited` is NOT the word: taken for a superclass field by ADR-0015 itself, shipped here for a day, and now in the glossary's `_Avoid_` line |

| [0041](0041-the-server-returns-the-set-and-the-client-stores-it.md) | A **stop-point set** is content the server returns and the **client** stores: `debug.list_stop_points {export:true}` emits it, the new `debug.arm_stop_points` takes it back, and nothing here touches the filesystem. A file under the project and a dotfile in `$HOME` were both rejected on the **safety model** — the watchdog, resume accounting and read-only enforcement all lean on process death being an unambiguous end of session, so persisted state is state no live process can vouch for. The format is the list of `debug.set_*` calls that would recreate the set, and the arming tool **replays them through the real handlers**, inheriting every refusal, clamp, deferral and read-only rule rather than reimplementing them; `ARMABLE_TOOLS` is a whitelist that also **routes**, so it cannot drift from what it permits. `export` is a flag and arming is a tool, under **ADR-0015**'s rule. Instance AND thread filters are dropped and named — #135 said only the first — leaving those entries **broader** than what was exported, which is stated above the block rather than below it. The subtler drop is `BreakpointInfo::method`, which is *resolved* rather than requested and is `Some` on every armed breakpoint: the first version wrote it into the args, turning `{line: 28}` into `{line: 28, method: "classify"}`, wrong on any build where that line has moved — found by reading a real exported block, fixed by keeping `arm_line`/`arm_method`. A disabled stop point is exported and NOT armed, because arming-then-disabling arms it for real in between. Outcomes are per entry (**DISC-14**) with deferral read from the session rather than sniffed from reply text (**TEST-46**), and lines are explicitly NOT checked against bytecode |

| [0042](0042-an-investigation-report-is-unredacted-and-says-so-first.md) | `debug.export_investigation` emits the session as one **Markdown** report — attach target, VM version, every stop point with its measured cost, the snapshots still held, the drift verdicts — because the findings are the deliverable and an investigation was otherwise readable once, by one reader, in a context window that gets summarised. **Unredacted, opening with a paragraph that says so before any content**, since a reader who scrolled past the warning has already read the payloads. Pattern-based redaction **rejected**: one that misses a secret is worse than none, because its output implies the file was cleaned — the same inversion ADR-0023 and ADR-0010 avoid by reporting a cost instead of altering an answer. Three properties make the warning act-on-able and each is asserted: it **names** payloads/tokens/`byte[]` credentials rather than saying "may contain sensitive data", it carries **why** there is no redactor (or the next person reads the absence as a gap to fill), and it may **never** imply the opposite — the test forbids "sanitised"/"safe to share" outright. A tool and not a `get_traces` flag, under **ADR-0015**: the stop points, costs and VM version are not in the buffer. The stop-point section is `list_stop_points`' own renderer, so it cannot drift, and it brings the staleness verdict for free. **It never clears** — the test calls it twice, because one call cannot tell reading from draining — and it **cannot** preserve a trace beyond the ring, which would need the write path ADR-0041 declined, so it states the loss (`trace_seq` against `traces.len()`) instead |
